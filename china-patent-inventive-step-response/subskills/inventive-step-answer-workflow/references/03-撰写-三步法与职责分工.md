# 正式意见陈述组装清单

本参考用于安排章节，文体及具体措辞由 [法律写作规范](../../legal-writing-style/SKILL.md) 维护。按本次争点决定篇幅和顺序，不要求固定章节齐全。

| 章节 | 何时设置及承担的任务 |
|---|---|
| 修改说明 | 确有修改时，说明修改文字、逐项原始依据及相关适应性修改 |
| 争点概述 | 有助于理解本次答复时简要设置，避免重复审查意见全文 |
| D1 与区别特征 | 说明分析起点的相关技术事实、公开范围及当前权利要求的差异 |
| 效果与技术问题 | 根据原始依据和因果关系推导实际技术问题，保留必要条件 |
| 技术启示 | 分析具体组合路径、作用条件、技术后果及获得完整方案的依据 |
| 其他因素 | 有相关证据时说明其与技术贡献的联系及对结论的影响 |
| 整体结论与请求 | 对已分析的权利要求整体作出结论，并提出与程序阶段一致的具体请求 |

章节可以合并。各独立权利要求及本次实质争点须得到覆盖；不按对比文件数量机械分段，不逐字重复表格与正文。

## 从属权利要求

审查意见对附加特征有独立理由，或独立权利要求存在风险时，针对相关附加特征作必要分析。独立权利要求的结论及其对从属权利要求的影响应准确交代，不为凑篇幅重复全部论述。

## 交接

写作前确定论点与依据，使用 [legal-writing-style](../../legal-writing-style/SKILL.md) 形成正式文本，随后交给 [patent-prose-polish](../../patent-prose-polish/SKILL.md) 校对。策略风险、待核实清单和方案比较另行提供给用户；正式文本中的必要证据限定仍须保留。
