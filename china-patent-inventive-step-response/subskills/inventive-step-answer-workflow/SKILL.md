# 创造性审查意见答复工作流

本 Skill 负责阶段衔接、必要模块的选择和交付质量。实体规则由专项 Skill 维护，正式文风由 [legal-writing-style](../legal-writing-style/SKILL.md) 维护；共同约束遵循[主 Skill 的共同约束与任务路由](../../SKILL.md)。

## 1. 确定本次范围

| 用户目标 | 执行范围 |
|---|---|
| 完整分析并提出方案 | 阶段 A—C，交付分析和建议 |
| 起草意见陈述或修改文本 | 阶段 A—D；复用已核实且仍有效的材料与分析 |
| 单一争点 | 按 [主 Skill 的共同约束与任务路由](../../SKILL.md) 直接进入专项模块 |
| 只修改表达或校对 | [legal-writing-style](../legal-writing-style/SKILL.md) 或 [patent-prose-polish](../patent-prose-polish/SKILL.md)；实体疑问另行核实 |
| 后续审查意见、驳回或复审前分析 | 在相应阶段加入前次答复复盘 |
| 生物技术案件 | 在阶段 B 的相应判断中叠加 [biotech-inventive-step](../biotech-inventive-step/SKILL.md) |

### 可选：用户主动要求的 DeepSeek 核查

仅当用户明确要求使用 DeepSeek/DS 核查，或明确选择本可选核查功能时，读取[可选核查操作说明](references/09-可选DeepSeek核查.md)并执行。用户未主动要求时，跳过本分支，不调用核查工具、不生成外发材料包，也不主动询问是否开启。普通“检查一下”“复核”“校对”按主流程处理；仅要求子agent时不自动选用外部DeepSeek。

此开关只控制外部核查，主agent原有事实核实、分析与校对职责继续执行。请求适用于用户指定的当前案件、文本和范围，不延伸为其他案件或后续轮次的默认设置。

## 2. 阶段 A：事实与证据核查

1. 取得审查意见及附件、当前有效权利要求、原始申请文件、D1/Dn；后续答复同时取得前次答复和修改文本。
2. 用 [office-action-analysis](../office-action-analysis/SKILL.md) 忠实复原逐权利要求审查论证链，记录通知书阶段、期限、申请日或优先权日及对比文件公开日。
3. 标明材料为全文、节选或缺失，关键事实逐项定位。审查意见没有说明的环节如实记录，不自行补成其观点。

产物：材料与版本清单、审查论证链、已核实事实和待核实事项。材料缺失只阻断依赖该材料的判断；继续可独立完成的工作，不用假设形成确定性法律结论。

## 3. 阶段 B：独立分析创造性

1. [closest-prior-art](../closest-prior-art/SKILL.md)：确定合理起点及其整体方案。
2. [distinguishing-features](../distinguishing-features/SKILL.md)：解释当前权利要求，与 D1 比对，形成区别特征、效果及技术问题的完整推导。
3. [obviousness-assessment](../obviousness-assessment/SKILL.md)：核查改进 D1 的启示、具体组合路径及其技术后果，回到完整权利要求评价。
4. 生物技术主题在相关步骤同步引入专题规则；有具体辅助证据时使用 [secondary-considerations](../secondary-considerations/SKILL.md)，再综合整体结论。

进入方案阶段前确认：

- 技术问题中的对象、条件和目标有证据支持，且未暗含解决手段；
- 非显而易见性论点说明了具体技术事实、因果关系和组合判断，并检验可能的反论；
- 说明书中的候选限定与当前权利要求的区别特征分开；
- 结论方向和证据强度分开表达，不能以材料不足推定有创造性。

缺少技术事实或因果依据时，回到相应模块补足或限制结论；不交由写作阶段补造理由。

## 4. 阶段 C：形成答复方案

1. 用 [challenge-examiner-reasoning](../challenge-examiner-reasoning/SKILL.md) 从已核实分析中选择主要论点、辅助论点及不建议主张的点，形成可转写为正面论述的依据。
2. 先判断是否需要修改。需要时使用 [claim-amendment-strategies](../claim-amendment-strategies/SKILL.md)，形成拟议文字、原始依据、范围影响及风险；无需修改时说明现有方案的论述基础。
3. 修改后重新解释权利要求，复核 D1，重做差异—效果—问题及技术启示判断，检查从属关系和必要的适应性修改。
4. 按实质差异比较可行方案。用户已有明确取舍时据此继续；尚需决定重要范围或商业取舍时，先完成可比较的方案再请求选择。

仅需分析的任务在此交付。内部报告可披露推理缺口、反论和策略风险；不把这些内容全部带入正式意见陈述。

## 5. 阶段 D：成稿与交付

1. 确认本次采用的权利要求版本及结论；仍依赖待核实事项的内容不得作为确定事实写入拟提交文本。
2. 用 [legal-writing-style](../legal-writing-style/SKILL.md) 起草，执行法言法语标准、正面论述及直接表达要求。按争点安排结构，实质回应本次审查意见。
3. 用 [patent-prose-polish](../patent-prose-polish/SKILL.md) 保守校对，保持事实、术语、引文、证据和结论强度；实体问题退回分析，范围或程序选择退回方案阶段。
4. 按交付清单核对正文、修改文本及附件的一致性。用户要求 Word/PDF 时，再使用文档工具并核验版面。
5. 有未解决事项时，明确标识为草稿并另列待核实清单；不将其表述为可直接提交的定稿。外部提交须另获授权。
