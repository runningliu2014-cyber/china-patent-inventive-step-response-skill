# 审查意见论证链分析

本 Skill 把审查意见转换为可核查的结构化记录。先准确复原审查员的观点，再评价其中是否存在缺口；不得把申请人的反驳预先写进审查员论证。

## 输入

优先读取：

- 审查意见正文及附件；
- 当前有效权利要求书；
- 审查员引用的 D1、D2/Dn；
- 前次答复和前次修改文本（非第一次答复时）。

缺少当前权利要求或关键引用内容时，将相关结论标为“待核实”。

## 分析流程

### 1. 建立基本信息

记录申请号、通知书类型、发文日、答复期限、被评价的权利要求及对比文件。对每篇对比文件区分：

- 审查员引用的具体版本；
- 公开日及其与申请日或优先权日的关系；
- 审查员实际援引的段落、附图或权利要求。

### 2. 逐权利要求复原论证链

每项独立权利要求单独记录，从属权利要求记录其附加特征被如何评价：

| 字段 | 内容 |
|---|---|
| 权利要求 | 当前编号及版本 |
| D1 | 审查员选定的最接近现有技术 |
| D1 公开内容 | 审查员认定的特征及出处 |
| 区别特征 | 审查员认定的差异 |
| 技术效果 | 审查员是否认定及如何认定 |
| 实际技术问题 | 审查员的表述 |
| 启示来源 | D2/Dn、同一文件其他部分或公知常识 |
| 结合理由 | 作用、动机、常规选择等原文 |
| 最终结论 | 对该权利要求的结论 |

没有写明的环节使用“未说明”，不要替审查员补齐。

### 3. 核对证据位置

将每项认定分成：

- **有明确出处**：可以定位到通知书或对比文件原文；
- **需要解释**：来自隐含公开、上位概念、附图理解或技术推断；
- **没有给出依据**：仅有结论性表述；
- **材料缺失**：当前无法核实。

“审查员引用了某段”与“该段确实公开了所述特征”分别记录。

### 4. 标记推理缺口

只标记缺口，不在本 Skill 中写长篇反驳。常见标签包括：

1. D1 公开认定待核实；
2. 区别特征遗漏、合并或错位；
3. 技术效果未分析或因果关系不明；
4. 实际技术问题过宽、包含解决手段或与效果不匹配；
5. D2 只公开手段，未说明其在该语境中的作用；
6. 结合动机、技术相容性或成功预期未说明；
7. 公知常识认定未针对具体领域和具体问题；
8. 多项区别特征的相互作用被割裂；
9. 前次答复的关键意见未得到回应；
10. 可能存在基于本申请方案反向拼接的路径。

缺口优先级按三项评估：证据确定性、对创造性结论的影响、修复该缺口所需的权利要求限缩程度。不要使用固定的错误类型等级。

## 输出

### 审查意见分析表

| 权项 | 审查员论证链 | 原文位置 | 独立核查状态 | 缺口标签 | 后续模块 |
|---|---|---|---|---|---|

随后给出：

- 已确认事实；
- 关键争议；
- 待核实材料；
- 建议交给 [closest-prior-art](../closest-prior-art/SKILL.md)、[distinguishing-features](../distinguishing-features/SKILL.md)、[obviousness-assessment](../obviousness-assessment/SKILL.md) 或 [challenge-examiner-reasoning](../challenge-examiner-reasoning/SKILL.md) 的问题。

## 边界

- 本 Skill 不预设审查员正确或错误。
- 不把说明书中未进入当前权利要求的特征当作现有区别特征。
- 不仅凭通知书措辞强硬程度判断授权前景。
- 不起草最终意见陈述；已核实的分析交给 [challenge-examiner-reasoning](../challenge-examiner-reasoning/SKILL.md) 组织论点，正式表达交给 [legal-writing-style](../legal-writing-style/SKILL.md)。
